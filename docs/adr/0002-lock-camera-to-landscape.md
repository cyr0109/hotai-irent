# 取還車拍照介面鎖定橫式

**狀態**：accepted

**背景**：iRent 現行 App 的取還車拍照介面是直式（見取車流程圖／還車流程圖的所有相機畫面），而 `iRent技術解決方案文件.md` 第 6.2 節先前的建議是「偵測到橫拿就讓快門失效、提示使用者直立拿好」，兩者一致指向直式。但實務上車身四角照要同時涵蓋完整車身與車牌，橫幅構圖明顯較寬鬆；而 6.2 節實測發現的真正問題（`RDL-9262右前 還.jpg`、`還2.jpg` 側躺 90 度導致 YOLO 漏判車牌）根源是**方向不一致**，不是「非直式」本身。

**決策**：取還車的所有拍照畫面一律鎖橫式，包含車外四角、車損特寫、車內前後座、加油卡/停車卡。使用者直拿手機時快門失效，提示轉為橫拿。

**為什麼**：
- 只要方向統一，後端 pipeline 的輸入就一致，6.2 節那批漏判案例的成因即消除；橫或直本身不是問題，混用才是
- 車身四角照是本案最關鍵的證據照，構圖寬鬆度直接影響「一張照片能不能同時涵蓋車身與車牌」，這決定了車牌完整性檢查的通過率
- 直式相機下使用者為了塞進整台車會退得更遠，反而惡化「太遠」與車牌解析度不足的問題

**後果（需連帶處理）**：
- 6.2 節的三層防線敘述要反向：主要防線的提示文案改為「請將手機橫拿」，最後防線的檔案檢查改為「**高 > 寬**即攔截」
- 現有直式拍照 UI（縮圖 slot、快門、提示浮層）需重新排版為橫式，這是本案前端工作量最大的單一項目
- 歷史照片（既有訂單、官方提供的訓練資料）多為直式，後端 pipeline 仍須保留 6.2 節建議的「0°/90°/270° 多角度嘗試」容錯，不能假設全部橫式
