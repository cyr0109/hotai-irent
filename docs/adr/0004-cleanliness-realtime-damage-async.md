# 還車時內裝清潔度即時判定並攔截，新車損比對改背景非即時

**狀態**：accepted

**背景**：環節二包含兩件事——內裝整潔度三分類與新車損偵測。原先的流程草稿同時寫著「環節二（非即時顯示）」與「偵測髒污 → 顯示異常預警 → 提醒使用者清理」，兩者互斥：非即時代表結果出來時使用者已經鎖車離開，提醒不到任何人。

**決策**：兩者拆開處理。
- **內裝清潔度：即時，且擋在鎖車之前。** 車內前/後座照上傳後立刻分類，判為「髒汙」就插入一頁攔截，讓使用者選擇整理後重拍或直接還車（後者記錄進訂單並走免責聲明）。
- **新車損比對：非即時，背景執行，不擋流程。** 使用者完成還車後才出結果，進後台預警並推播給使用者，同時決定綠色里程點數。

**為什麼**：
- 「提醒使用者清理」這個需求只有在**車門還開著、人還在現場**時才有意義，所以它必須即時且必須擋在鎖車前，否則等於放棄，髒車只能派人清
- 兩者的運算成本差一個量級：清潔度是單張輕量分類（秒級），新車損是「ORB/SIFT 對齊 + SSIM diff + YOLO confirm」兩層架構（見 `iRent技術解決方案文件.md` 1.1），讓使用者站在車邊等後者不切實際——尤其地下停車場常常沒訊號
- 車損判定有誤判風險，非即時讓爭議進入後台複核流程，而不是在現場跟使用者對質

**後果**：使用者端需要一個事後預警的落地點（推播 + 訂單明細的車況紀錄頁），否則非即時的結果沒有出口。
