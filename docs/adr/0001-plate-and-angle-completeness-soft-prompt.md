# 環節一「角度覆蓋」與「車牌完整性」檢查，採兩階段軟提示+被動記錄，不做硬擋或主動推播

**狀態**：accepted（適用範圍已由 ADR 0003 擴大——本文的軟提示路線現在涵蓋**所有**照片內容層級的檢查項，不只角度覆蓋與車牌完整性）

**背景**：環節一需要判斷使用者拍攝的4張外觀照片，是否涵蓋全部4個角度、以及是否至少有一張拍到完整車牌，以確保留下足夠的車況證據。但現實環境（例如狹窄停車格、車後被遮擋）常讓使用者無法拍到理想角度或車牌，若採硬擋+強制重拍，會卡住這類使用者無法達成的情境。

**決策**：
1. 兩者都不做硬擋。偵測到缺項時，先顯示建議性重拍提示（具體點名缺什麼），使用者可以只補拍缺的那一項（不用整組4張重來）；使用者選擇跳過才顯示一份合併免責聲明，具體列出缺項，要求使用者按下明確同意按鈕（非被動顯示）才能送出，同意動作與時間戳會被記錄。
2. 後台採被動記錄——缺項與同意紀錄只存進訂單資料，不主動推播通知客服或建立待處理清單，等真正發生客訴/理賠糾紛時才由客服調閱查看。

**為什麼**：
- 強制重拍對「物理上真的拍不到」的使用者沒有意義，只會製造挫折感，解決不了停車格空間不足這種現實限制
- 免責聲明+明確同意動作，能在不犧牲使用者體驗的前提下，為iRent保留「使用者已被告知風險、仍選擇繼續」的舉證力
- 主動推播代表要為這個小機率的軟提示情境投入人工介入成本，跟「軟提示、不強制」的整體定位矛盾——如果問題嚴重到需要主動介入，邏輯上一開始就該做硬擋，不該用軟提示的形式包裝
